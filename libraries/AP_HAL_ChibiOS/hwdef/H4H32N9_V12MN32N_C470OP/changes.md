### 2.4 Motor Thrust Expo — Updated

![image.png](attachment:837378d5-4ae5-41b0-a1de-4ab3d1bd370a:image.png)

```
MOT_THST_EXPO   0.78   (was 0.5613)
```

The value **0.78** was generated by **Mission Planner Initial Parameters** tool with 32" prop and Quad X frame as input. This is the recommended method per the Methodic Configurator guide (step `15_motor.param`).

The expo value linearises the thrust curve: `T(a) = expo × a + (1 − expo) × a²`. A higher value (0.78) reflects the more non-linear thrust curve of large-diameter low-pitch props.

### 2.5 Hover Throttle — Reset

```
MOT_THST_HOVER  0.2   (was 0.3490)
```

The value **0.2** is the Mission Planner estimate for this motor/prop combination. ArduPilot **automatically learns** the real value during the first stable hover in ALTHOLD mode (`MOT_HOVER_LEARN = 2` = learn and save). After ~2 minutes of stable hover the parameter converges and saves automatically.

After the value is learned, **update `INS_HNTCH_REF` to match** the new `MOT_THST_HOVER`.

> Reference: [ArduPilot Hover Throttle](https://ardupilot.org/copter/docs/ac_throttle.html)
Reference: Methodic Configurator — step `20_throttle_controller.param`
>

### 2.6 Motor Spin Values — No Change

```
MOT_SPIN_ARM  0.12   (unchanged)
MOT_SPIN_MIN  0.15   (unchanged)
```

Source model already had values appropriate for CAN FOC ESCs. These values **must still be verified on the bench** before first flight:

1. **MOT_SPIN_ARM**: Props OFF — use Mission Planner Motor Test, raise throttle % from 0 until all motors spin reliably. That % (as a fraction) = MOT_SPIN_ARM.
2. **MOT_SPIN_MIN**: Props ON (on a scale) — raise until consistent, stable thrust is produced. That % = MOT_SPIN_MIN.
3. Rule: `MOT_SPIN_MIN ≥ MOT_SPIN_ARM + 0.03` (currently 0.15 − 0.12 = 0.03 ✓)

### 2.8 Harmonic Notch Filter — Conservative Initial Estimate

```
INS_HNTCH_FREQ   31    (was 38)          ← estimated from 32" prop hover RPM
INS_HNTCH_REF    0.2   (was 0.231798)    ← must equal MOT_THST_HOVER
INS_HNTCH_ATT   40    (was 100)          ← conservative start
INS_HNTCH_BW    15    (was 22)           ← conservative start
INS_HNTCH_HMNCS  3    (was 15)           ← 1st + 2nd harmonics only
INS_HNTCH_MODE   1    (unchanged — throttle-based)
INS_HNTCH_OPTS  16    (unchanged — double-notch)
INS_GYRO_FILTER 20    (unchanged)
INS_ACCEL_FILTER 10   (unchanged)
```

**`INS_HNTCH_FREQ 31 Hz`** — Estimated hover RPM for the MN8017 with 32" props:

- Hover throttle ≈ 20% of max thrust → ~3370 g/motor
- From TMotor thrust table interpolation at ~3370 g: ≈ 1875 RPM
- Notch frequency = 1875 RPM ÷ 60 = **31 Hz**
- (Previous 38 Hz was for the old powerplant; 32" props spin slower for the same thrust)

**`INS_HNTCH_REF 0.2`** — Must equal `MOT_THST_HOVER`. The throttle-based notch tracks frequency as:

```
f_notch = FREQ × sqrt(throttle / REF)
```

At hover (throttle = REF), the notch sits exactly at FREQ. After the first hover updates `MOT_THST_HOVER`, update `INS_HNTCH_REF` to the same learned value.

**`INS_HNTCH_ATT 40 dB`** — Reduced from 100 dB. Starting conservatively; aggressive attenuation before confirming the correct frequency adds unwanted phase lag.

**`INS_HNTCH_BW 15 Hz`** — Narrower bandwidth to start. Widen only after log review confirms the noise peak is broad.

**`INS_HNTCH_HMNCS 3`** — Bitmask `0b0011` = harmonics 1 and 2 only. Large 32" props generate most noise at the fundamental and 2nd harmonic; higher harmonics are minimal.

> ⚠️ These are **pre-flight estimates** per Methodic Configurator step `18_notch_filter_setup.param`. They must be refined using the Filter Review Tool after the first flight log.
> 

> Reference: [ArduPilot Harmonic Notch Filter](https://ardupilot.org/copter/docs/common-imu-notch-filtering.html)
Reference: Methodic Configurator — Section 6.16
>

### 2.10 Battery Low Threshold — Revised

```
BATT_LOW_VOLT   43.5   (was 43.2)
BATT2_LOW_VOLT  43.5   (was 43.2)
```

Low voltage threshold raised from 43.2 V (3.6 V/cell) to **43.5 V** (3.625 V/cell × 12 cells). This provides an earlier RTL warning to account for faster voltage sag under load with aged cells or in cold conditions.

---

### 2.11 Flight Mode Channel — Disabled

```
FLTMODE_CH   0   (added — was not set)
```

Setting `FLTMODE_CH = 0` disables RC flight mode switching via a dedicated transmitter channel. Flight mode changes are handled exclusively via GCS or companion computer. This prevents accidental mode changes from RC stick input during autonomous operations.

### 2.12 GPS GNSS Constellation and SBAS — Updated

```
GPS_SBAS_MODE    0   (added — SBAS disabled)
GPS1_GNSS_MODE   5   (added — GPS + Galileo)
GPS2_GNSS_MODE   5   (added — GPS + Galileo)
```

- **`GPS_SBAS_MODE 0`** — Disables SBAS corrections. SBAS coverage and reliability varies by region and can cause GPS instability when the augmentation satellite geometry is poor.
- **`GPS1_GNSS_MODE 5` / `GPS2_GNSS_MODE 5`** — Bitmask `0b00000101` = GPS (bit 0) + Galileo (bit 2). Restricts both receivers to GPS and Galileo constellations. Galileo provides better geometry and accuracy than GLONASS in most operating regions and produces a cleaner, more stable CAN bus packet rate.
